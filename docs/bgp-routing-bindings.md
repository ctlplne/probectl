# Router-local selected-RIB bindings

A BMP collector authenticates each router with mTLS. The control plane uses the
current tenant-owned collector/source assignment to find its base routing
context. A packet's distinguisher or BGP identifier cannot select a tenant,
canonical router, routing context or wire serializer.

Read the complete operator configuration with:

```text
GET /v1/entity-contexts/{context_id}/bgp-routing-bindings?collector_agent_id={collector}&source_ref={authenticated-origin}
```

This requires `entities.read` for the base and every mapped current context.
The response contains the base context/router and a `manifest`. A null manifest
means the strict global-source default. A configured manifest contains a
server-generated `epoch`, `assigned_at` and complete `bindings`.

Replace the configuration with `PUT` on the same path. It requires
`agent.write` for the base, every current target and every proposed target:

```json
{
  "collector_agent_id": "collector-identity",
  "source_ref": "authenticated-router-identity",
  "expected_epoch": "",
  "bindings": [
    {
      "context_id": "11111111-1111-4111-8111-111111111111",
      "router_id": "22222222-2222-4222-8222-222222222222",
      "distinguisher": "0000000000000000",
      "bgp_identifier": "192.0.2.1",
      "families": [1, 2],
      "source_format": "frr_loc_rib_v1"
    }
  ]
}
```

Use an empty `expected_epoch` only for initial configuration. Subsequent writes
must supply the exact current epoch from readback; a stale epoch returns 409.
Binding IDs and the replacement epoch are generated by the server. An empty
`bindings` array withdraws all selectors and does not restore a legacy fallback.
Replacement, retirement of prior routing generations and the tenant audit
append commit atomically. A failed audit or incomplete response admission rolls
back the replacement. An authorized base owner can withdraw a reference to a
deleted target; readback never invents policy attributes for a deleted context.

The distinguisher is the exact opaque eight-byte BMP value in hexadecimal.
`bgp_identifier` is the identifier in the BMP **per-peer header**, separate from
the identifier inside a fabricated BGP OPEN. For FRR, use the configured
`bgp router-id` of the global or VRF instance. Its fabricated OPEN can contain
`0.0.0.0` while the per-peer header contains the actual router ID; copying the
OPEN value would leave the source unbound. A zero header identifier is supported
when that is the source's explicit configuration. `families` declares the
complete supported unicast set: 1 for IPv4, 2 for IPv6.

An omitted or empty `source_format` uses strict negotiated capabilities.
`frr_loc_rib_v1` describes FRR's known selected-RIB serializer, whose virtual OPEN
can contain empty ADD-PATH capability data and omit monitored MP families. This
operator-selected profile uses the complete declared families and the known
non-ADD-PATH/non-ENHE wire grammar while retaining both original OPENs and all
information TLVs. Unknown formats fail closed; senders cannot enable a profile.
The stored format must still match the current binding for stream updates and
route reads.

Routing state stays private until each family receives its own complete initial
view and End-of-RIB. A selected RIB describes routing information, not proof of
forwarding. Configuration alone does not assert a live router or a current
route. The receiver resolves non-global keys through the complete current operator
binding before decoding. Updates must still match their stored generation
selector, including refusals; an unknown selector cannot reset a sibling.
Complete mapped physical sender/flow surfaces remain under qualification.

Operations share the configured Explorer execution, response, memory and tenant
fairness admission. Complete metadata and retained state also use the routing
store's finite byte/work/state budget. There is no binding-count truncation:
refused admission returns an error with no partial replacement.

When native MCP is configured, `bgp_routing_bindings` reads the configuration and
`bgp_routing_bindings_replace` performs the same epoch-conditional replacement.
Both require an authenticated tenant user and the same current context
permissions. They share the REST admission and audit path. Existing egress
consent and redaction apply to sender/operator values; canonical stored UUIDs
retain their structural identity. The tools do not grant source freshness.

In Admin → Routing source bindings, choose an owned base context and the current
collector/origin identities, then read the current epoch and complete binding
array. The editor replaces the entire array without truncation. Withdrawing
every selector requires explicit confirmation. Changing tenant or source clears
the draft; stale responses cannot populate a different source editor. Read-only
operators can inspect configuration without receiving write controls.

The CLI preserves the complete array and exact epoch for both named commands
and raw API operations:

```sh
probectl routing-bindings read CONTEXT --query collector_agent_id=COLLECTOR --query source_ref=ORIGIN --json
probectl routing-bindings replace CONTEXT --body-file bindings.json --json
```

The body file contains the same complete replacement object as REST. The CLI
does not infer tenant identity or a source format from packet metadata.

## Original-flow witnesses (preview transport)

The restricted agent evidence RPC accepts a `flow_capture_v1` batch containing
only the original record digest and exporter/protocol/domain/source/destination
dimensions. Its mTLS certificate supplies the tenant and sender. The sender
must own the unique current exporter before the service reads its router's
selected RIB. The digest covers the complete original protobuf record before
enrichment or exporter-clock clamping, including retained future fields.

The complete ordered response contains capture keys and first processing
clocks. It contains no routes or read permissions. First receipts are durable:
retries reuse the original observation; erased payloads and an unavailable
first observation cannot be filled by later routing data. The raw bus consumer
can resolve an independently authenticated witness or seal unavailable. A
claimed bus agent ID cannot create positive canonical routing evidence.

The collector worker preserves every eligible configured source in the raw
batch and pages identity observations over the existing transport. Its optional
routing-witness adapter runs independently of raw publication and reports
receipt/error counts in collector statistics. The production runtime wrapper
has not yet enabled that adapter.

This transport foundation has not yet activated flow ingestion attachment or
historical query surfaces. Current reader authorization, actual flow-sender
proofs and complete served-surface acceptance remain required for that release.
