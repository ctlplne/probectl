# Router-local selected-RIB bindings

A BMP collector authenticates each router with mTLS. The control plane uses the
current tenant-owned collector/source assignment to find its base routing
context. A packet's distinguisher or BGP identifier cannot select a tenant,
canonical router, routing context or wire serializer.

Read the complete operator configuration with:

```text
GET /v1/entity-contexts/{context_id}/bgp-routing-bindings?collector_agent_id={collector}&source_ref={authenticated-origin}
```

This requires `entities.read` for the base and every mapped current context.
The response contains the base context/router and a `manifest`. A null manifest
means the strict global-source default. A configured manifest contains a
server-generated `epoch`, `assigned_at` and complete `bindings`.

Replace the configuration with `PUT` on the same path. It requires
`agent.write` for the base, every current target and every proposed target:

```json
{
  "collector_agent_id": "collector-identity",
  "source_ref": "authenticated-router-identity",
  "expected_epoch": "",
  "bindings": [
    {
      "context_id": "11111111-1111-4111-8111-111111111111",
      "router_id": "22222222-2222-4222-8222-222222222222",
      "distinguisher": "0000000000000000",
      "bgp_identifier": "192.0.2.1",
      "families": [1, 2],
      "source_format": "frr_loc_rib_v1"
    }
  ]
}
```

Use an empty `expected_epoch` only for initial configuration. Subsequent writes
must supply the exact current epoch from readback; a stale epoch returns 409.
Binding IDs and the replacement epoch are generated by the server. An empty
`bindings` array withdraws all selectors and does not restore a legacy fallback.
Replacement, retirement of prior routing generations and the tenant audit
append commit atomically. A failed audit or incomplete response admission rolls
back the replacement. An authorized base owner can withdraw a reference to a
deleted target; readback never invents policy attributes for a deleted context.

The distinguisher is the exact opaque eight-byte BMP value in hexadecimal.
`bgp_identifier` is the monitored peer's IPv4 identifier, including `0.0.0.0`
when the source uses a virtual selected-RIB peer. `families` declares the complete
supported unicast cohort: 1 for IPv4, 2 for IPv6.

An omitted or empty `source_format` uses strict negotiated capabilities.
`frr_loc_rib_v1` describes FRR's known selected-RIB serializer, whose virtual OPEN
can contain empty ADD-PATH capability data and omit monitored MP families. This
operator-selected profile uses the complete declared families and the known
non-ADD-PATH/non-ENHE wire grammar while retaining both original OPENs and all
information TLVs. Unknown formats fail closed; senders cannot enable a profile.
The stored format must still match the current binding for stream updates and
route reads.

Routing state stays private until each family receives its own complete initial
view and End-of-RIB. A selected RIB describes routing information, not proof of
forwarding. Configuration alone does not assert a live router or a current
route. Non-global receiver activation and complete mapped sender/flow surfaces
remain under qualification.

Operations share the configured Explorer execution, response, memory and tenant
fairness admission. Complete metadata and retained state also use the routing
store's finite byte/work/state budget. There is no binding-count truncation:
refused admission returns an error with no partial replacement.
